# 🏚 Base Structure Template

Это фундамент, базовая структура Go проектов с базой данных и миграциями, готовая к продакшену.

---
### 📜 Описание состава

- Настроен общий конфиг - подгрузка данных из config.yaml + .env (данные для запуска сервера и БД);
- Настроено создание пула подключений к БД (метод New() в db.go)
- Написан базовый main.go для приложения: инициализация всех параметров, поднятие http-сервера, а также `graceful shutdown` приложения;
- Написан отдельный main.go для запуска миграций: установка флагов команд в командной строке, подключение к БД и выполнение самих команд относительно флагов, а также `сборка в бинарник`;
- Плюсом написаны sql-файлы с миграциями как пример;
- Описан Dockerfile, где собираются оба бинарника;
- Описан docker-compose для запуска контейнеров с сервисами: БД -> Миграции -> API;
- Описан makefile со справочной информацией по командам - для простоты запуска.

---
### 🏆 Результат работы

Запускается из docker: 
- собираются бинарники приложения и отдельный бинарник с миграциями.
- поднимается БД на PostgreSQL
- отрабатывают миграции 
- после миграций поднимается API, и можно работать.

Всё выполнено в чистой идиоматичной архитектуре Go-проектов, с применением паттерна "Сервисный слой".

> Предпочтительно использовать утилиту make для запусков (описан makefile). 
> Однако можно и в ручную (в makefile можно посмотреть, какие команды для чего нужны).

---
### ⚒ Инструкция по использованию:

1. После команды `git clone` в склонированном проекте удалите файлы go.mod и go.sum;
2. Создайте новый go.mod со своим названием модуля (`go mod init <ваше_название>`)
3. Переименуйте часть с названием модуля в импортах на свой:
	- import "<ваш_модуль>/interal/config"				// файлы app/main.go, migrate/main.go, db.go
	- import "<ваш_модуль>/internal/database"			// файл migrate/main.go
4. Подгрузите все зависимости командой `go mod tidy`
